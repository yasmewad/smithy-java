Reference · canonical vocabulary

Glossary

The words this track uses, defined once. Every term is anchored to the real smithy-java source or the internal KT doc, so the definitions stay honest.

Shape
The unit of a Smithy model: a structure, a member (field), an operation, a service. A shape says what the data is, never how it looks on the wire. KT doc §2; smithy.io/2.0
Model
The abstract description of a whole service — its operations and their inputs/outputs — written in the Smithy language, independent of any wire format. KT doc "Getting Started"; smithy.io/2.0
Code generation (“codegen”)
The step that reads a model and writes Java for you: builder classes, accessors, and the plumbing to send/receive each operation. Entry point JavaCodegenPlugin (build plugin name "java-codegen"), modes CLIENT/SERVER/TYPES. codegen/codegen-plugin/…/JavaCodegenPlugin.java; KT doc §16
Protocol
The rules for turning an operation call into bytes and back. smithy-java ships restJson1, restXml, AWS JSON 1.0/1.1, AWS Query, and rpcv2Cbor. The same shapes serialize under any of them. KT doc §11
ClientProtocol<RequestT, ResponseT>
The one interface a client protocol must satisfy. Six members: id() → ShapeId; payloadCodec() → Codec (may be null); messageExchange(); createRequest(...); setServiceEndpoint(...); deserializeResponse(...). client/client-core/…/client/core/ClientProtocol.java
ClientProtocolFactory<T extends Trait>
Builds a protocol inside a client builder. Declares id() → ShapeId and createProtocol(ProtocolSettings settings, T trait). A protocol’s nested Factory is what gets registered for discovery. client/client-core/…/client/core/ClientProtocolFactory.java
ProtocolSettings
The small carrier passed to a factory at construction; notably exposes service() → ShapeId, the service the protocol is being built for. client/client-core/…/client/core/ProtocolSettings.java
MessageExchange<RequestT, ResponseT>
A marker interface binding a protocol to a compatible transport’s request/response types; the pipeline validates compatibility at construction. client/client-core/…/client/core/MessageExchange.java; KT doc §8
Schema
A trimmed-down runtime representation of a Smithy shape — just enough to drive serde. Sealed hierarchy (RootSchema, MemberSchema, deferred/resolved variants). Carries a dense memberIndex() for array dispatch. core/…/core/schema/; KT doc §2
Schema-directed serde
The design where Schema is the first argument to every serde method. Generated code pushes members; the protocol codec reads the schema to decide wire format. Traits are never inspected at write time — they’re precomputed into extensions. KT doc §2
ShapeSerializer / ShapeDeserializer
The visitor interfaces a codec implements. Serialization is “push” (serializeMembers(ShapeSerializer)); deserialization is a callback (readStruct(schema, state, consumer) then switch(member.memberIndex())). core/…/core/serde/ShapeSerializer.java, ShapeDeserializer.java
Codec
The bridge between structures (which carry schemas) and bytes; produces ShapeSerializer/ShapeDeserializer. Interface lives in core; implementations (JsonCodec, Rpcv2CborCodec, XmlCodec) live in codecs/. A new protocol often reuses an existing codec. core/…/core/serde/Codec.java; codecs/; KT doc §5
SchemaExtensionProvider / SchemaExtensionKey
The SPI that attaches precomputed, protocol-specific data to a schema once at construction (e.g. UTF-8 field-name byte tables). Accessed via schema.getExtension(KEY). Examples: SmithyJsonSchemaExtensions, CborSchemaExtensions, HttpBindingSchemaExtensions. KT doc §2 (Extension System)
SPI / ServiceLoader / META-INF/services
The universal discovery mechanism. A protocol becomes “known” by registering its factory in a service file. Real example: client-rpcv2-cbor/…/META-INF/services/software.amazon.smithy.java.client.core.ClientProtocolFactory contains the single line software.amazon.smithy.java.client.rpcv2.RpcV2CborProtocol$Factory. Missing registration = feature silently absent. verified service file; KT doc "Code Conventions"
REST base vs RPC base
REST protocols (restJson1, restXml) extend HttpBindingClientProtocol, which auto-maps @http* traits to wire locations. RPC protocols (AWS JSON, AWS Query, rpcv2Cbor) extend HttpClientProtocol directly and serialize the whole body. client/client-http/…/HttpClientProtocol.java; client/client-http-binding/…/HttpBindingClientProtocol.java; KT doc §11
Protocol compliance tests
The authoritative correctness bar. protocol-test-harness/ runs Smithy-defined @httpRequestTests/@httpResponseTests against real client/server code. Run with ./gradlew :protocol-test-harness:test. A unit test that passes but fails compliance is a bug. protocol-test-harness/; KT doc "Correctness First"
Trait
An annotation on a shape in the model (e.g. @httpHeader, @required, @timestampFormat). Protocols are also identified by a trait — e.g. rpcv2Cbor by Rpcv2CborTrait.ID, which a factory’s id() returns. KT doc §2, §6; RpcV2CborProtocol.java
TypeRegistry
Maps an error discriminator (__type in JSON, x-amzn-errortype header) to the right error builder, populated at codegen time. Used by deserializeResponse to turn an error response into the correct modeled exception. KT doc §2 (Polymorphic Error Deserialization)
A term here still fuzzy? Ask your teacher to expand it with a concrete example from the codebase.
